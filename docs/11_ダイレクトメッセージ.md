# 第11回 ダイレクトメッセージ（DM）

> 開始タグ：`lesson10-step2` → 到達タグ：`lesson11-step2`
> ※ これまでの回より SQL が長い「発展」の回です。仕組みの理解を優先し、SQL はファイルを読み解く形で進めて構いません。

## この回のゴール

- 「2人だけが読み書きできる」データを、RLS で表現できる
- ルールが複雑な処理を **データベースの関数（RPC）** にまとめ、`supabase.rpc()` で呼べる
- 会話一覧と、メッセージ画面で DM を送受信できる

## 講義

### 1. テーブルの形

```text
conversations（2人の会話。1組につき1行）
| id | user_a | user_b | last_message | last_message_at | last_read_at_a | last_read_at_b |

messages（会話の中の1通ずつ）
| id | conversation_id | sender_id | content | created_at |
```

- **`user_a` には小さい方の id を入れる**（`check (user_a < user_b)`）。こうすると「安堂と佐藤」「佐藤と安堂」が別の会話として2つできてしまうのを `unique (user_a, user_b)` で防げる
- `last_message` などは、メッセージが追加されたときに **トリガー** が更新する（会話一覧を速く出すため）

### 2. 「参加者だけ」の RLS

```sql
-- 会話：自分が user_a か user_b の行だけ読める
using ((select auth.uid()) in (user_a, user_b))

-- メッセージ：その会話の参加者なら読める（参加しているかは関数で確かめる）
using (public.is_conversation_member(conversation_id))
```

### 3. RPC（データベースの関数）を使う理由

| 処理 | アプリで書くと | 関数にすると |
|---|---|---|
| 会話を開く（無ければ作る） | 「探す → 無ければ作る」の2回の通信。2人が同時に開くと2つできるかも | `get_or_create_conversation(相手)` の1回。`on conflict do nothing` で重複しない |
| 既読にする | 自分が a か b かで更新する列を変える必要がある | `mark_conversation_read(会話)` の1回 |

```js
const { data: conversationId } = await supabase.rpc('get_or_create_conversation', { other_user: otherUid });
```

- 関数は `security definer`（管理者の権限）で動くので、中で必ず `auth.uid()` を確かめる
- `revoke … from public, anon` で、ログインしていない人には実行させない

### 4. 未読の判定（ビュー `conversation_list`）

「最後のメッセージが **相手から** 来ていて、自分が最後に読んだ時刻より **新しい**」なら未読。
一度も読んでいない（`null`）ときは `coalesce(…, '-infinity')`（大昔）として比べます。

#### 📄 `supabase/migrations/0007_direct_messages.sql`（新規）

```sql
-- =====================================================================
-- 0007_direct_messages.sql（第11回・発展）DM（ダイレクトメッセージ）
--
-- ① conversations …… 2人の会話（1組につき1行）
-- ② messages ………… 会話の中の1通1通
-- ③ RLS ＋ grant …… 「参加している2人だけ」が読み書きできる
-- ④ 関数（RPC）……… 会話を作る／既読にする（ルールが複雑なので DB の関数にまとめる）
-- ⑤ トリガー ……… メッセージが届いたら、会話の「最後のメッセージ」を更新する
-- ⑥ conversation_list ビュー …… 会話一覧（相手の名前・未読かどうか付き）
-- =====================================================================

-- ① conversations
--   user_a と user_b は「小さい方の id を user_a」と決めておく（check 制約）。
--   → 同じ2人の会話が、AとBの順番違いで2つできてしまうのを防げる（unique 制約）
create table public.conversations (
  id               uuid primary key default gen_random_uuid(),
  user_a           uuid not null references public.profiles (id) on delete cascade,
  user_b           uuid not null references public.profiles (id) on delete cascade,
  last_message     text,
  last_message_at  timestamptz,
  last_sender_id   uuid,
  last_read_at_a   timestamptz,  -- user_a が最後に読んだ時刻（null ＝ まだ一度も読んでいない）
  last_read_at_b   timestamptz,  -- user_b が最後に読んだ時刻
  created_at       timestamptz not null default now(),
  constraint ordered_pair check (user_a < user_b),
  constraint unique_pair unique (user_a, user_b)
);

-- ② messages
create table public.messages (
  id              uuid primary key default gen_random_uuid(),
  conversation_id uuid not null references public.conversations (id) on delete cascade,
  sender_id       uuid not null default auth.uid() references public.profiles (id) on delete cascade,
  content         text not null,
  created_at      timestamptz not null default now(),
  constraint message_length check (char_length(trim(content)) between 1 and 1000)
);

create index messages_conversation_idx on public.messages (conversation_id, created_at);

-- ③ RLS ＋ grant
alter table public.conversations enable row level security;
alter table public.messages enable row level security;

-- 会話：自分が参加している行だけ読める（追加・更新は ④⑤ の関数だけが行う）
create policy "参加者だけ読める"
  on public.conversations for select to authenticated
  using ((select auth.uid()) in (user_a, user_b));

-- 「この会話に自分が参加しているか」を確かめる関数（ポリシーの中で使う）
--   security definer にしておくと、ポリシーの中から conversations を読んでも
--   RLS が二重にかからず、シンプルに判定できる
create function public.is_conversation_member(conv_id uuid)
returns boolean
language sql
stable
security definer set search_path = ''
as $$
  select exists (
    select 1 from public.conversations c
    where c.id = conv_id and (select auth.uid()) in (c.user_a, c.user_b)
  );
$$;

create policy "参加者だけ読める"
  on public.messages for select to authenticated
  using (public.is_conversation_member(conversation_id));

create policy "参加者が自分の名前でだけ送れる"
  on public.messages for insert to authenticated
  with check (sender_id = (select auth.uid()) and public.is_conversation_member(conversation_id));

grant select on public.conversations to authenticated;
grant select, insert on public.messages to authenticated;

-- ④-1 会話を取得（無ければ作る）。戻り値は会話の id
--   アプリからは supabase.rpc('get_or_create_conversation', { other_user: '...' }) で呼ぶ
create function public.get_or_create_conversation(other_user uuid)
returns uuid
language plpgsql
security definer set search_path = ''
as $$
declare
  me uuid := (select auth.uid());
  a uuid := least(me, other_user);
  b uuid := greatest(me, other_user);
  conv_id uuid;
begin
  if me is null then raise exception 'ログインが必要です'; end if;
  if other_user = me then raise exception '自分自身とは会話できません'; end if;

  insert into public.conversations (user_a, user_b)
  values (a, b)
  on conflict (user_a, user_b) do nothing;   -- すでにあれば何もしない

  select id into conv_id from public.conversations where user_a = a and user_b = b;
  return conv_id;
end;
$$;

-- ④-2 既読にする（自分の側の「最後に読んだ時刻」を今にする）
create function public.mark_conversation_read(conv_id uuid)
returns void
language sql
security definer set search_path = ''
as $$
  update public.conversations
  set last_read_at_a = case when user_a = (select auth.uid()) then now() else last_read_at_a end,
      last_read_at_b = case when user_b = (select auth.uid()) then now() else last_read_at_b end
  where id = conv_id and (select auth.uid()) in (user_a, user_b);
$$;

-- 関数はまず全員から実行権限を外し、ログイン済みの人にだけ与える
revoke execute on function public.get_or_create_conversation(uuid) from public, anon;
revoke execute on function public.mark_conversation_read(uuid) from public, anon;
revoke execute on function public.is_conversation_member(uuid) from public, anon;
grant execute on function public.get_or_create_conversation(uuid) to authenticated;
grant execute on function public.mark_conversation_read(uuid) to authenticated;
grant execute on function public.is_conversation_member(uuid) to authenticated;

-- ⑤ メッセージが追加されたら、会話の「最後のメッセージ」を更新する
--   送った本人は、その時点で既読扱いにする
create function public.handle_new_message()
returns trigger
language plpgsql
security definer set search_path = ''
as $$
begin
  update public.conversations
  set last_message    = left(new.content, 100),
      last_message_at = new.created_at,
      last_sender_id  = new.sender_id,
      last_read_at_a  = case when user_a = new.sender_id then new.created_at else last_read_at_a end,
      last_read_at_b  = case when user_b = new.sender_id then new.created_at else last_read_at_b end
  where id = new.conversation_id;
  return new;
end;
$$;

create trigger on_message_created
  after insert on public.messages
  for each row execute procedure public.handle_new_message();

-- ⑥ 会話一覧ビュー（ログイン中の人から見た「相手」と「未読かどうか」）
create view public.conversation_list
with (security_invoker = true)
as
select
  c.id,
  other.id           as other_user_id,
  other.display_name as other_name,
  other.photo_url    as other_photo_url,
  c.last_message,
  c.last_message_at,
  c.last_sender_id,
  -- 未読 ＝ 最後のメッセージが相手から来ていて、自分が最後に読んだ時刻より新しい
  (
    c.last_message_at is not null
    and c.last_sender_id <> (select auth.uid())
    -- coalesce(x, '-infinity') … まだ読んだことが無い（null）なら「大昔」として比べる
    and c.last_message_at > coalesce(
      case when c.user_a = (select auth.uid()) then c.last_read_at_a else c.last_read_at_b end,
      '-infinity'
    )
  ) as unread
from public.conversations c
join public.profiles other
  on other.id = case when c.user_a = (select auth.uid()) then c.user_b else c.user_a end;

grant select on public.conversation_list to authenticated;
```

import { useEffect, useRef, useState } from 'react';

import { PageHeader } from '@/components/PageHeader';
import { cn, formatRelativeTime } from '@/lib/utils';

/**
 * 1対1のメッセージ画面（components/DMThreadClient.jsx）
 * otherUid … 相手の uid（/messages/[uid] の uid）
 */
export const DMThreadClient = ({ otherUid }) => {
  const { user } = useAuthStore();
  const { currentConversationId, messages, openConversation, sendMessage } = useDmStore();
  const other = useProfileStore((s) => s.profiles[otherUid]);
  const fetchProfile = useProfileStore((s) => s.fetchProfile);
  const [content, setContent] = useState('');
  const [error, setError] = useState(null);
  const [sending, setSending] = useState(false);
  const bottomRef = useRef(null);

  // 相手のプロフィールと会話を読み込む
  useEffect(() => {
    fetchProfile(otherUid);
    openConversation(otherUid).catch((e) => setError(e.message));
  }, [otherUid, fetchProfile, openConversation]);

  // メッセージが増えたら一番下までスクロールする
  useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: 'smooth' });
  }, [messages.length]);

  const handleSend = async (e) => {
    e.preventDefault();
    const text = content.trim();
    if (!text || !currentConversationId) return;
    setSending(true);
    try {
      await sendMessage(currentConversationId, text);
      setContent('');
    } catch (err) {
      window.alert(err.message);
    } finally {
      setSending(false);
    }
  };

  return (
    <main className="mx-auto flex min-h-[calc(100vh-56px)] max-w-2xl flex-col border-x">
      <PageHeader title={other?.displayName ?? 'メッセージ'} />

      <div className="flex-1 space-y-3 px-4 py-4 md:px-6">
        {error && <p className="py-8 text-center text-destructive">{error}</p>}
        {!error && messages.length === 0 && (
          <p className="py-8 text-center text-muted-foreground">最初のメッセージを送ってみましょう</p>
        )}
        {messages.map((m) => {
          const mine = m.senderId === user?.uid;
          return (
            // 自分のメッセージは右・青、相手のメッセージは左・グレー
            <div key={m.id} className={cn('flex flex-col', mine ? 'items-end' : 'items-start')}>

                  'max-w-[80%] whitespace-pre-wrap break-words rounded-2xl px-4 py-2 text-[15px]',
                  mine ? 'rounded-br-sm bg-primary text-primary-foreground' : 'rounded-bl-sm bg-muted',
                )}
              >
                {m.content}
              </p>
              <span className="mt-1 text-xs text-muted-foreground" suppressHydrationWarning>
                {formatRelativeTime(m.createdAt)}
              </span>
            </div>
          );
        })}

      <form onSubmit={handleSend} className="sticky bottom-16 flex gap-2 border-t bg-background p-3 md:bottom-0">

          value={content}
          onChange={(e) => setContent(e.target.value)}
          placeholder="メッセージを入力"
          rows={1}
          maxLength={1000}
          className="flex-1 resize-none rounded-md border border-input bg-background px-3 py-2 text-sm outline-none focus:ring-2 focus:ring-ring"
        />

          <Send className="size-4" />
        </Button>
      </form>
    </main>
  );
};

```js
/**
 * DM（ダイレクトメッセージ）のストア（stores/dmStore.js）— 第11回
 *
 * 会話一覧は conversation_list ビュー、メッセージは messages テーブルを使う。
 * 会話を「作る」のは DB の関数 get_or_create_conversation（rpc で呼ぶ）。
 */
import { create } from 'zustand';
import { createClient } from '@/lib/supabase/client';

const supabase = createClient();

const toConversation = (row) => ({
  id: row.id,
  otherUserId: row.other_user_id,
  otherName: row.other_name,
  otherPhotoURL: row.other_photo_url,
  lastMessage: row.last_message,
  lastMessageAt: row.last_message_at,
  lastSenderId: row.last_sender_id,
  unread: row.unread,
});

const toMessage = (row) => ({
  id: row.id,
  conversationId: row.conversation_id,
  senderId: row.sender_id,
  content: row.content,
  createdAt: row.created_at,
});

const useDmStore = create((set, get) => ({
  // --- State ---
  conversations: [],
  conversationsLoading: false,
  currentConversationId: null,
  messages: [],

  // --- 会話一覧 ---
  // まだ1通もやり取りしていない会話（last_message_at が null）は出さない
  fetchConversations: async () => {
    set({ conversationsLoading: true });
    const { data, error } = await supabase
      .from('conversation_list')
      .select('*')
      .not('last_message_at', 'is', null)
      .order('last_message_at', { ascending: false });
    if (error) console.error('fetchConversations', error.message);
    set({ conversations: (data ?? []).map(toConversation), conversationsLoading: false });
  },

  // --- 1つの会話 ---
  // 相手の uid から会話を開く（無ければ DB の関数が作ってくれる）
  openConversation: async (otherUid) => {
    set({ currentConversationId: null, messages: [] });
    const { data: conversationId, error } = await supabase.rpc('get_or_create_conversation', {
      other_user: otherUid,
    });
    if (error) throw new Error(`会話を開けませんでした：${error.message}`);
    set({ currentConversationId: conversationId });
    await get().fetchMessages(conversationId);
    return conversationId;
  },
  fetchMessages: async (conversationId) => {
    const { data, error } = await supabase
      .from('messages')
      .select('*')
      .eq('conversation_id', conversationId)
      .order('created_at', { ascending: true });
    if (error) console.error('fetchMessages', error.message);
    set({ messages: (data ?? []).map(toMessage) });
  },
  // 送信（sender_id は DB の default auth.uid() が入る）
  sendMessage: async (conversationId, content) => {
    const { error } = await supabase.from('messages').insert({ conversation_id: conversationId, content });
    if (error) throw new Error(`送信に失敗しました：${error.message}`);
    await get().fetchMessages(conversationId);
  },
}));

export default useDmStore;
```

## 確認クイズ

1. `user_a < user_b` の制約がないと、何が起きうる？ → 同じ2人の会話が、順番違いで2つできてしまう
2. `get_or_create_conversation` を `security definer` にしたのはなぜ？ → `conversations` に insert のポリシーが無く、アプリから直接は作れないようにしているから（作るのは関数だけ）
3. 関数の中で `auth.uid()` を確かめるのはなぜ？ → 管理者の権限で動くので、RLS の代わりに自分でチェックする必要があるから

## よくあるつまずき

| 症状 | 原因 | 対処 |
|---|---|---|
| `Could not find the function public.get_or_create_conversation` | SQL 未実行・引数名の違い | 引数名は `other_user`（`{ other_user: uid }`） |
| `permission denied for function` | `grant execute` 漏れ | 0007 の SQL の grant を実行 |
| 会話一覧が空 | まだ1通も送っていない会話は出さない仕様 | 1通送ってから確認 |
| 「自分自身とは会話できません」 | 自分のプロフィールからメッセージを開いた | 他人のプロフィールから開く |
